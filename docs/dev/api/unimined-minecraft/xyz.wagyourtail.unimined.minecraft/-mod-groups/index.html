ModGroups

object ModGroups

Launch-side consumption of the environment's mods { "<id>" { } } groups — the selection rule plus the two loader serializations, shared by every launch surface (run<Name>, the test<Name> JUnit twin, and IDE-emitted run configs) so the formats can't drift.

  • classpathGroups-capable loaders (fabric-family) take classpathGroupsValue as a system property — fabric-loader #585.

  • modGroupsEnv-capable loaders (forge-family) take modClassesEntries appended to that env var (MOD_CLASSES id%%dir pairs — Loom loom.mods / NFRT parity).

fun selected(environment: MinecraftEnvironment, loadedMods: Set<String>, prod: Boolean): List<ModGroupSpec>

The groups one run loads: loadedMods (RunConfig.loadedMods) selects a subset by name, an empty set loads every declared group. Mod groups are a dev-launch channel — prod runs launch the shipped jar, where dev source-set outputs on the classpath would double the mod's classes (the run wiring itself keeps sourceSet.output off prod classpaths for the same reason), so a prod run selects nothing.
