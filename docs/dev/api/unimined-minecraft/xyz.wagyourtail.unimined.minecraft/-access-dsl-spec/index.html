AccessDslSpec

open class AccessDslSpec @Inject constructor

Inline access-declaration DSL behind access { } — rules are stored semantically (kind + member + descriptor), not as file text, so the generated document can be emitted in whichever format the env's loader consumes: accessWidener/classTweaker on AW-family loaders, FML accesstransformer.cfg on AT-family. Directives with no equivalent in the consumed format are dropped with a build-log note (interface injection/enum extension have no AT analog).

Declared rules ride the same channel as file-declared access files — applied to the dev Minecraft artifact, shipped in the mod jar (the accessWidener field on fabric-family / FMLAT manifest on forge), and propagated to aux environments through combineWith.

Jar path this env's merged access document ships at — overrides the loader's conventional canonical path ({modid}.accesswidener, META-INF/accesstransformer.cfg) where the loader's metadata declares the path; {modid} expands. All access { } calls' rules merge into ONE canonical doc, so setting this twice with different paths is a config error (for multiple shipped files use from(path) { output = ... }). Ignored where the loader has no access-file convention.

emit
Link copied to clipboard
fun emit(format: AccessDslSpec.Format, dropped: MutableList<String> = mutableListOf()): List<String>

Emit the collected rules as file lines in format — no header, no trailing newline. AW directives emit their declared form on AW/CT; on AT they map to the closest FML entry (accessible → public, extendable → protected-f, mutable → public-f — the AT model couples access+finality, so mutable widens to public as a side effect). CT directives and AT entries only emit on their native formats; cross-format rules return in dropped for the caller to log.
