fun splitEnvironmentSourceSets()

Loom splitEnvironmentSourceSets() parity — retarget this project to a compile-time split environment:

  • main becomes the common source set — Side.COMMON — compiling against the client∩server intersection artifact, so common code can't reference client-only classes;

  • a client environment compiles against the full client jar and sees main's output through the implicit-parent combine (its classesDirs reach client's compile classpath, the full output reaches its runtime classpath). The env is marked isAuxEnv: it inherits main's loader/dependency/access sections, produces no separate published artifact or mod metadata, and gets no remapClientJar — the mod artifact is main's;

  • jar folds client output in (and remapJar/remapSourcesJar mirror the jar's copy spec, so the fold carries through production), sourcesJar gains the client sources, and the test source set inherits the client's classpath view;

  • client-side runs conventionally bound to main (runClient, runProdClient, a user's runs { client {} }) launch through the client environment; runServer/ runProdServer stay on main — on modern bundled-server versions the common jar is the server's view.

Providers without genuinely split distributions (declared legacydist jars, dev bundles, BuildTools outputs, non-mergeable conversion products) alias COMMON to their single artifact — the compile-time fence then only guards client-only code the shared jar genuinely lacks.

Idempotent — a second call is a no-op. A pre-existing sourceSet("client") env is repurposed as the split client (its MinecraftEnvironment.side becomes Side.CLIENT).
