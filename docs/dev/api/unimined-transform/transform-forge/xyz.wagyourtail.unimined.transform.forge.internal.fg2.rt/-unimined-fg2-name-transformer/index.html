UniminedFg2NameTransformer

open class UniminedFg2NameTransformer : IClassTransformer, IClassNameTransformer

Dev-launch class-name translator, registered in the DeobfuscationTransformer slot of FMLDeobfTweaker.injectIntoClassLoader (see deobfTransformerNameOrNull).

Why: a unimined dev jar is dev-namespace-named (feather), but FG2-era FML probes carry srg names — ObjectHolderRegistry.scanTarget's Class.forName("net.minecraft.init.Blocks") and friends. LaunchClassLoader.findClass resolves the probe's resource via untransformName and defines under transformName, so both must yield the dev name. Fed CL: srg dev makes map srg->dev — matching the remapper's member-map keying (rawFieldMaps are srg-keyed, so mapFieldName/mapMethodName resolve srg probes to dev names the same way ObfuscationReflectionHelper expects).

Collision guard: a probe that already IS a dev name can still hit an srg key — feather's net/minecraft/potion/Potion is srg's Potion -> StatusEffect. Re-mapping it loads the wrong class entirely. The jar's own entries are the dev-namespace ground truth, so a probe whose .class resource exists on the classpath passes through untranslated; only genuine misses (srg probes) go through the map.

Self-contained on purpose:transformName runs inside findClass — including the load that defines THIS transformer and any helper it might call. Reaching into UniminedFg2 from here re-enters the loader mid-definition (ClassCircularityError), so the reflective resolution is inlined and re-entrance-guarded.
